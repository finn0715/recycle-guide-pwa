# 앱 진입점

페이지·레이아웃·공통 스타일과 coach 인식/도움/음성 및 기존 analyze/identify의 HTTP 진입을 소유한다. 화면 상태는 클라이언트 제어기, 배출 규칙과 외부 모델은 데이터·서버 모듈의 책임이며 페이지에서 복제하지 않는다.

기본 서버 페이지는 RecyclingCallApp을 렌더링한다. 실시간 통화 설정과 검수 자료는 `/api/call`의 서버 처리기가 제공하며 키는 서버에만 둔다. 기존 PhotoCoachApp 소비자는 검증된 공개 카탈로그를 props로 받는다. 키·모델 연결 객체를 props나 공개 환경변수로 넘기지 않는다. 브라우저 음성·제어기는 마운트 effect의 자원이며 StrictMode의 정리 후 재실행에서도 새로 만들어야 한다. 정리된 마이크/제어기를 재사용하지 않는다.

API route는 Node 런타임의 처리기를 연결하는 얇은 경계다. 이미지 해독·Realtime WebSocket을 Edge로 임의 전환하지 않는다. 기존 두 API의 소비자 계약은 새 기본 페이지 연결과 별개로 유지한다.

레이아웃 변경 시 문서 기본 한국어·viewport와 선택 언어의 main.lang을 유지하고 사진·현재 행동·버튼의 관계를 확인한다. 실제 multipart/JSON이 처리기에 도달하는지, 성공·실패의 no-store와 음성의 WAV/맥락 헤더가 유지되는지 검사한다. 경로 타입 변경은 npm run typecheck로 생성까지 확인하고 마운트·정리 재실행도 회귀 검사한다.
