# 클라이언트의 사진·진행·음성 수명

사진 정규화·객체 URL, 물건별 선택 이력, 요청 취소와 응답 검증, 녹음·재생을 소유한다. UI 스타일·원본 규칙·외부 모델 호출은 여기서 구현하지 않는다. 서버 키나 원본 규칙 모듈을 import하지 않고 서버 페이지가 준 검증 카탈로그와 공통 계약을 사용한다.

coach-controller가 현재 세션·물건·단계·revision·요청 ID를 관리한다. 같은 종류의 실물을 합치지 않고 같은 사진 묶음의 물건 전환은 각 진행을 유지한다. 정정은 해당 지점 이후 선택을 버리고 유효 이력을 재생한다. 사진 재인식·수동 물건 교체는 이전 관찰과 진행을 자동 이전하지 않는다. 초기화·이탈은 사진·질문·녹음·재생을 끝낸다.

음소거/재생 중단은 오디오 수명만 바꾸며 이미 받은 도움 답·입력을 지우지 않는다. 맥락이 바뀌면 이전 전사·답·음성은 취소/폐기한다. 취소 뒤 늦게 승인된 getUserMedia도 자신이 받은 트랙만 닫고 새 녹음을 건드리지 않는다. 재생 종료로 다음 단계에 가지 않는다.

녹음은 명시 버튼에서만 시작하고 완료 버튼에서 전송한다. 20초 제한 도달·취소는 자동 전송하지 않는다. public/coach-pcm-worklet.js는 AudioWorklet 정적 자산이며 장치 샘플레이트의 프레임을 받는다. 공통 WAV 모듈로 24kHz 단일 채널 16bit PCM을 만들고 해독·길이·무음을 검사한다. 프레임·트랙·노드·타이머는 해당 캡처가 끝날 때 정리한다.

이미지는 전체 비율과 방향을 유지하며 바이트 크기와 픽셀 수를 따로 확인한다. 해독 불가를 빈 성공 미리보기로 만들지 않는다. 파일 선택 취소는 오류가 아니며 URL은 교체·삭제·초기화 때 해제한다. 오류에서도 유효한 입력을 유지하고 자동 재전송·영구 저장·서비스워커 복원은 하지 않는다.

서버의 성공 응답도 공통 스키마·카탈로그·현재 맥락을 검증한다. 음성은 상태·Content-Type·맥락 헤더·WAV 형식까지 대조한 뒤 재생한다. 카탈로그 변경은 재시작을 요구한다. 실제 multipart/서버 처리기를 잇는 통합 검사에서는 모델 경계만 대체한다.

기존 quick-guide-controller/guide-controller 소비자는 유지한다. 기존 상세 흐름의 knownItemId를 중간 null 응답 때문에 잃지 않고, 다른 물건 응답으로 이전 대화를 계속 확정하지 않는 회귀 검사도 유지한다.

## 기본 실시간 통화

`recycling-call`은 WebRTC 통화 수명을 소유한다. 통화 시작에서 마이크 권한을 요청하고 자동 발화 감지로 대화를 잇는다. 카메라는 별도 선택이며 약 3초마다 정지 사진을 보내고 최근 두 이미지 메시지만 유지한다. 업로드 사진 전송은 카메라 공유를 끈다. 종료·이탈·연결 실패는 마이크·카메라·타이머·데이터 채널·peer·서버 통화를 정리한다. 늦은 권한 승인과 연결 응답도 해당 세대가 끝났으면 닫는다. 이 통화는 위 기존 coach의 녹음 완료 버튼과 검수 문장 재생 계약을 사용하지 않는다. 실물 기기 검증과 합성 입력 검증을 구분한다.

기본 통화의 언어는 런타임 생성 시 ko/en으로 고정한다. 언어 변경 시 새 런타임을 사용하며 연결 중 전환은 UI에서 잠근다. 선택 사진의 연결 대기와 취소 시 폐기는 UI가 관리한다.
