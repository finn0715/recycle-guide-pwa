# 공통 계약

기본 /api/call은 기존 coach 카탈로그 계약과 별도다. 현재 SDP·종료 토큰 계약의 구현은 src/lib/server/recycling-call.ts와 src/lib/client/recycling-call.ts에 있으며 docs/contracts.md에 기록한다. 이 디렉터리의 WAV/선택 검증이 통화 발화에 적용되는 것으로 주장하지 않는다.

브라우저·서버가 공유하는 ID·상태·좌표·카탈로그·선택 이력·요청/응답·제한을 소유한다. 모델 SDK·서버 키·기기 사진/음성 처리·배출 규칙 원본은 가져오지 않는다.

coach 계약은 범주와 실물·사진·부품 식별자를 구분한다. 같은 범주라는 이유로 실물 ID를 합치지 않는다. 좌표 범위뿐 아니라 현재 사진과 부모 물건 참조를 검사한다. 모델 임시 인덱스를 서버 ID로 그대로 통과시키지 않는다. 기존 10종 ItemId와 새 범주 ID는 다른 소비자 계약이다.

카탈로그는 활성 규칙/출처·단계/선택/답 참조, 종료/보류, 허용 사실과 도달 가능한 비순환 경로를 실행 중 검사한다. 선택 이력은 시작부터 재생하며 현재 단계 주장과 대조한다. 부분 결과를 합칠 때 이미 준비한 부품은 유지하지만 정정으로 경로가 없어지면 제거한다. 알려지지 않은 ID·카탈로그 버전 불일치를 자동 보정하지 않는다.

도움 답의 문장·선택·출처는 현재 단계의 검수 답과 일치해야 한다. speech cue는 현재 단계 또는 허용 답만 가리키며 자유 문장 필드를 추가하지 않는다. 스키마·제한 변경은 양쪽 해독·런타임 검증·실제 요청 연결 검사를 함께 갱신한다.

기존 analyze의 ready 필수 안내·부품 출처와 다른 상태의 null 규칙, identify의 중복 없는 10종 목록 계약도 유지한다. 검증 실패를 숨기기 위해 상태 모순·참조 조건을 느슨하게 만들지 않는다.

기본 통화의 `call-language.ts`는 ko/en 검증과 언어별 첫인사를 정의한다. `/api/call` 언어 헤더 생략은 ko이며 지원하지 않는 값은 외부 요청 전에 거절한다.
