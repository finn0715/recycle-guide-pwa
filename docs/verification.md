### 로컬 HTTPS·프로덕션·비밀정보

`npm run https:prepare` 종료 코드 0 뒤 `npm run dev:https -- --port 3443`로 실제 개발 서버를 실행했다. ### 최종 정정·취소 회귀 확인

`c4e1621`의 프로덕션 서버에서 실제 모델로 펌프 사진을 다시 확인했다. 사진만 보낸 요청은 `needs_info`, 명확한 4조건 문장은 `ready`, 종이 라벨로 바꿔 말한 혼합 정정과 비움 질문을 만들어 달라는 요청은 각각 `needs_info`·안내 없음이었다. 네 요청 모두 HTTP 200이고 requestId·no-store 검사를 통과했다. 같은 준비 상품사진과 가상 답변을 사용했으며, 현장 정확도 시험은 아니다.

### 사진·대화·키 처리

앱에는 사진·대화를 영구 저장하는 DB·업로드 저장소·대화 이력 기능을 두지 않았다. 현재 화면의 메모리와 분석 요청 처리에 사용하며 초기화·페이지 이탈 시 정리한다. 분석을 누르면 사진과 대화가 앱 서버를 거쳐 OpenAI로 전송된다. 앱 자체의 비보관과 외부 서비스의 처리·보관 정책은 다르다. `store: false`만으로 외부의 모든 보관이 없다고 주장하지 않는다.

OpenAI 호출은 서버에서만 수행한다. Responses 요청은 `store: false`, SDK 로그는 `off`, 자동 재시도는 0회이며 서버 응답은 `Cache-Control: no-store`다. 클라이언트는 오류에 가짜 안내를 대신 표시하지 않는다. 키를 브라우저 코드나 오류 응답에 넣지 않는다.

최종 통합 커밋 `c4e1621`의 빌드 후 비밀정보 검사는 종료 코드 0이었다. 서버 키 설정, `.env` Git 제외·미추적을 확인했고 추적 파일·클라이언트 빌드 81개에서 실제 키가 발견되지 않았다. 검사 기록에는 키 값이 없다.
