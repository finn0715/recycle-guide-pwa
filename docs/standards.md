# 변경과 검증 규칙

현재 기본 통화는 결정 0006을 따른다. 검수 자료에 근거해 생성 음성을 실시간 재생하며 기존 coach의 허용 문장 대조와 다른 경계다. 아래 단계·WAV·카탈로그 규칙은 해당 기존 소비자에 적용한다. 기본 통화는 미디어 수명·늦은 응답·이미지 맥락·끼어들기와 실제 제공자 동작을 검증한다.

## 판단 책임

- 기존 analyze/coach API에서 모델은 품목과 사실 후보만 제공한다. 배출 문구·출처는 검수된 서버 자료에서 구성한다. 모델이 만든 안내를 검증 없이 통과시키는 변경은 허용하지 않는다.
- 사실 사전의 확인 방식이나 규칙 선택기를 바꿀 때 사진만 있는 입력·모름·미검수 조건·근거 충돌의 회귀 검사를 함께 실행한다. 실패를 없애기 위해 사용자 확인 검사나 대표 조건을 느슨하게 만들지 않는다.
- 기준을 변경하면 공식 원문 조건과 확인 날짜, 규칙의 검수 상태, 부품별 출처 연결을 함께 검토한다. 지역과 제품 조건을 확인하지 않은 검색 요약을 근거로 넣지 않는다.
- 요청·응답 타입과 제한은 `src/lib/contracts`를 양쪽에서 소비한다. UI에 배출 규칙 사본을 두거나 클라이언트 전용 제한만으로 서버 검증을 대신하지 않는다.
- 새 제품·수정·초기화 동작은 단일 상태 제어기와 요청 버전 검사를 거치게 하고, 화면의 별도 상태로 완료를 확정하지 않는다. 테스트용 모델과 시연 데이터는 실제 사용자 성공 응답의 대체 수단이 아니다.

- 기존 coach의 선택 이력과 음성 응답은 공통 검증을 거친다. UI에서 별도 완료 상태를 만들거나 자유 음성 문장을 직접 재생하면 경계 위반이다. WAV 형식·제한 변경은 브라우저와 서버가 공유하는 해독기를 함께 갱신한다.
- 사진 위치는 정규화 방향·비율과 실제 표시 영역을 함께 검사한다. 새 도해는 현재 부품과 동작에 맞는지 화면에서 확인하고 무관한 예시로 검사를 통과시키지 않는다.

## 코드와 의존성

TypeScript와 저장소의 npm 잠금파일을 기준으로 설치한다. 재현은 `npm ci`로 하고, 의존성 변경 시 매니페스트와 잠금파일을 함께 변경한다. 외부 모델 변경은 실제 계정 접근과 품목 흐름을 확인하며, 연결 실패를 이유로 임의 교체하지 않는다.

서버 전용 모듈·키·원본 규칙 모듈을 클라이언트에서 직접 가져오지 않는다. 화면은 서버 페이지가 제공하는 검증된 공개 안내 카탈로그를 소비한다. 사진·녹음·대화·진행의 디스크 저장, 브라우저 영구 저장, 내용 로그를 추가하는 변경은 기존 비보관 정책과 충돌하므로 먼저 사용자 결정을 받는다. 오류 응답에는 내부 스택·원본 제공자 오류를 넣지 않는다.

기본 언어는 한국어이며 기본 통화 UI의 상태·오류·행동은 선택한 한국어·영어로 일치시킨다. 브랜드와 기술 식별자를 제외한 장식용 영어를 늘리지 않는다. 배출 분류는 색과 함께 글로 표현하며 사진 선택 대안을 유지한다. 코드·로그·문자열에 이모지를 넣지 않는다.

## 검증 완료 조건

통합 코드 변경은 `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`의 실제 종료 코드 0으로 확인한다. 문서만 수정했으면 근거·링크·기록 정합성을 확인하고 같은 코드의 빌드를 반복하지 않는다.

규칙 변경은 대표 조건과 인접한 미지원·미검수 조건을 함께 시험한다. API 변경은 잘못된 요청과 출력, 사용자 발화 근거, 서비스 오류·시간 제한·동시 처리 정리를 확인한다. 상태 변경은 수정·초기화·중복 전송·실패 후 재시도·늦은 응답을 확인한다. 클라이언트와 서버를 잇는 계약 검사는 실제 multipart 해독과 규칙 선택까지 포함하고 외부 모델 경계만 대체할 수 있다.

모델 연결·프롬프트·품목 인식 변경에는 영향받는 대표 사진의 실제 호출이 필요하다. 준비된 사진·가상 답변·대체 모델 응답을 명시한다. 빌드 성공, 실제 API 연결, 화면 검증, 실물 기기 검증을 별도 결과로 기록하며 정확도·환경 효과를 추정해 채우지 않는다.

브라우저 검증은 Aside의 `aside repl`을 기본으로 한다. 매 동작 뒤 새 `snapshot()`으로 상태를 확인하고 시각 판단은 캡처를 열어 확인한다. Aside가 작동하지 않으면 확인된 한계를 알리며 임의로 다른 자동화 도구로 바꾸지 않는다. 데스크톱의 390px·820px·가로 화면 검증은 물리 기기 카메라 검증을 대신하지 않는다.

음성 변경은 실제 제공자 연결·대응 문장·중단을 확인한다. API 파일 생성, 브라우저 재생 상태, 사람 청취, 실물 마이크는 별개 근거로 기록한다. 기기·계정 등 외부 조건으로 못 한 항목은 미실시로 남긴다. 사진·녹음·개인 대화 본문을 QA 증거에 저장하지 않는다.

로컬 HTTPS 변경은 체인·localhost/현재 IP SAN·CA 재사용·개인키 권한·안전한 실패를 검사한다. 시스템 또는 기기 CA 신뢰를 자동 설치하지 않는다. 인증서 파일이 Git 추적에 들어가면 검사 실패다.

## 저장소와 기록 보존

기존 학생 기록·대회 자료와 작성 중인 사용자 파일을 보존한다. 도구로 구현한 내용을 학생이 직접 조사·개발한 실적으로 바꾸지 않는다. 삭제·정리 전에 변경 파일과 대상 경로를 확인하며 별도 작업이 섞인 디렉터리는 강제로 지우지 않는다.

브랜치는 `<prefix>/<짧은-영문-kebab-case>`, 커밋은 `<prefix>: <실제 변경 내용>`이다. prefix는 `feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `build`, `ci`, `perf`, `revert` 중 선택한다. 브랜치·커밋·PR 제목과 본문에 도구명·에이전트명·AI 작성 표시·공동 작성 서명을 넣지 않는다. 원격 삭제·공개 게시·외부 메시지 전송은 별도 사용자 지시 없이 수행하지 않는다.

배너에는 행동을 반복 권유하는 문장이나 장식용 소개를 덧붙이지 않는다. 짧은 제목·버튼에는 불필요한 마침표를 붙이지 않고 질문의 물음표와 오류·고지 본문 문장부호는 유지한다. 제목 줄바꿈은 화면 폭에 맡기며 종료 뒤에도 동일한 홈 구조로 복귀한다.
