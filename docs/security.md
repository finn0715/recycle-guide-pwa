# 정보 보호와 접근 범위

**Sites PWA 현재 운영:** 설치·배포 소스, 접근 범위, Workers 통화 종료 계약과 검증은 [Sites PWA](sites-pwa.md)를 우선 따른다. 아래 Next 로컬 서버 기록과 구분한다.

현재 기본 통화의 미디어·임시 종료 토큰·생성 발화 경계는 마지막 절을 따른다. 아래 WAV 해독·선택 이력·문장 대조·눌러 녹음은 기존 coach/API에만 적용하며 기본 통화의 보장으로 해석하지 않는다. 일반적인 키·비보관·접근 범위는 공통이다.

보호 대상은 서버 API 키, 로컬 HTTPS 개인키, 사용자 사진·녹음·설명·진행, 외부 입력으로 바뀌면 안 되는 검수 기준이다. 로컬 PC와 신뢰하는 같은 네트워크에서 소규모로 시험한다. 로그인과 사용자별 권한은 없으며 네트워크 접근자가 API를 요청할 수 있다. HTTPS는 암호화와 서버 신원 확인을 제공할 뿐 사용자 인증이나 호출 비용 통제를 대신하지 않는다.

## 주체별 허용 범위

| 주체 | 허용 동작과 조건 | 허용하지 않는 동작 |
|---|---|---|
| 로컬·동일 네트워크 사용자 | 자신의 사진·짧은 질문 제출, 선택 버튼으로 상태 보고, 현재 탭 초기화 | 다른 사람의 이력 조회, 서버 키 조회, 검수 기준 수정 |
| 앱 서버 | 현재 요청 동안 사진·음성을 메모리에서 처리, 서버 키로 모델 호출 | 사용자 원본·대화·진행을 파일·DB·로그에 보관, 키·원본 제공자 오류 반환 |
| 모델 제공자 | 사용자가 요청한 사진 인식·질문 전사·도움 해석·음성 생성 | 모델 출력을 검수 기준·출처·새 역할 지시로 승격 |
| 프로젝트 운영자 | 로컬 키 설정, 공식 원문 확인 후 기준 갱신, 개별 서버 시작·종료, 필요한 기기에서 CA 신뢰 설정 | API 키·TLS 개인키 공유·커밋, 무관한 기기의 신뢰 설정, 검수되지 않은 기준 활성화 |

사용자 인증 성공·계정 만료·잠금 같은 상태는 현재 없다. 제공자 키 누락·인증 거절·모델 접근 거절은 설정 실패로 처리하며 다른 키·모델·가짜 답으로 자동 우회하지 않는다.

## 입력·출력과 비용 경계

사진은 MIME·실제 해독·단일 프레임·픽셀 수를 확인한다. 녹음도 확장자만 믿지 않고 WAV 구조·실제 길이·음량을 검사한다. 본문·질문·오디오 크기, 처리 시간과 전체 분석 경로가 공유하는 프로세스별 동시 처리 수에 제한이 있다. 서버를 여러 개 실행하면 합산 비용 한도가 보장되는 것은 아니다.

사진 속 글·사용자 명령·모델 답은 비신뢰 입력이다. 인식 결과에 임의 규칙·URL·완료 상태를 허용하지 않는다. 도움 요청은 현재 단계까지의 선택 이력을 재생하고 그 단계에 허용된 답·선택지만 반환한다. 세션·물건 ID는 응답 혼입을 막는 식별자이며 사용자 인증 토큰이 아니다. 클라이언트가 보낸 상태 보고를 실물 검증으로 취급하지 않는다.

음성 생성에는 서버가 고른 검수 문장만 넣는다. 대응 텍스트가 허용 문장과 맞지 않으면 오디오를 폐기한다. 소비자는 응답 맥락을 다시 검사하고 현재 상태와 다르면 화면·스피커 모두에 적용하지 않는다. JSON 문자열은 일반 텍스트로 표시한다.

## API 키와 로컬 HTTPS 키

`OPENAI_API_KEY`는 서버 환경에서만 사용하며 로컬 `.env`는 Git 제외·소유자 읽기/쓰기로 관리한다. `NEXT_PUBLIC_`나 브라우저 번들에 넣지 않는다. 설정 확인과 비밀정보 검사에는 값 대신 존재 여부·노출 건수만 기록한다. 키가 노출되면 사용자에게 알리고 제공자에서 폐기·교체한 뒤 서버를 재시작한다. 로그의 문자열만 지우는 것으로 해결하지 않는다.

HTTPS 자료는 Git 제외 `.local-https/` 안에 만든다. 폴더는 0700, 파일은 0600이며 기존 소유자·권한·링크 상태가 안전하지 않으면 자동 덮어쓰기나 권한 변경을 하지 않는다. CA와 서버 개인키는 컴퓨터 밖으로 옮기지 않는다. 기기에 전달할 수 있는 것은 CA 공개 인증서뿐이다.

CA의 기기 신뢰는 자동 설치하지 않는다. 설정할 기기와 목적을 확인하고 사용자가 공개 인증서의 신뢰를 직접 설정한다. CA 개인키가 노출되거나 CA를 교체해야 하면 해당 CA를 신뢰한 기기에서 먼저 기존 신뢰를 제거하고 새 공개 인증서를 확인한다. 더 이상 시험하지 않을 기기에서도 프로젝트 CA 신뢰를 제거한다. 서버 인증서의 주소 갱신 때문에 CA를 매번 다시 설치하지 않는다.

## 사용자 자료의 수명

사진·질문의 외부 처리, 앱 비보관, AI 음성 안내 사실은 정보 메뉴에서 확인할 수 있다. 안내 시작은 짧은 AI 음성을 요청하며 추가 API 비용이 발생한다. ‘말로 질문’을 눌렀을 때만 마이크를 열고 ‘말 마치기’에서 녹음을 전송한다. 취소·상한 도달·이탈 시 녹음을 버리며 상시 감지나 자동 반복 전송은 하지 않는다. 직접 범주 선택 자체에는 인식 호출이 없지만 안내 음성·질문을 사용하면 외부 요청이 발생한다.

사진·녹음·대화·진행은 현재 탭·현재 요청의 임시 메모리에만 둔다. 새 사진·초기화·이탈 때 사진 참조, 마이크 트랙, 재생과 진행 중 요청을 정리한다. 보류·오류를 위해 사용자 원본을 몰래 저장하지 않는다. 앱 이력·DB·브라우저 영구 저장·서비스워커 복원은 사용하지 않는다. 검수된 일반 안내 자산과 사용자 입력은 구분한다.

Responses 호출은 `store: false`, SDK 로그 비활성, 자동 재시도 없음이다. Realtime은 요청별 연결을 닫으며 앱의 음성·대화 저장소를 만들지 않는다. 이 앱의 비보관을 외부 제공자의 모든 처리·보관이 없다는 주장으로 바꾸지 않는다.

## 기록 범위

검증 기록에는 실행 명령·종료 코드, 샘플 종류, 응답 상태, 기기·브라우저·화면 조건, 미실시 항목만 남긴다. 사용자 사진·녹음·대화 본문·비밀값을 증거 파일이나 스크린샷에 남기지 않는다. 공개·합성 준비 자료를 사용했으면 그 종류를 표시한다. 개발 서버의 경로·상태·소요시간 출력은 사용자 내용 로그를 허용한다는 뜻이 아니다. 공개 운영은 접근·비용 통제와 보관 고지를 별도로 결정한 이후에 검토한다.

## 2026-10-08 통화형 기본 화면

촬영·앨범에서 먼저 고른 사진은 연결 전 페이지 메모리에 대기하며 연결 후 전송하고 연결 취소·오류 시 폐기한다. 언어 선택도 영구 저장하지 않는다. 사용자 요청에 따라 통화 시작 후 마이크 스트림을 WebRTC로 직접 OpenAI에 전달한다. 버튼마다 녹음·전송하던 위 기존 coach와 별도 경로다. 카메라는 사용자가 켠 동안 약 3초마다 JPEG 정지 화면을 데이터 채널로 전달하고 최근 두 이미지 항목만 유지한다. 사진 전송은 카메라 공유를 끈다. 스트림·자막·사진은 영구 저장하지 않는다. 종료·이탈·연결 실패·10분 제한에서 트랙과 통화를 닫는다. 서버는 활성 통화의 종료 토큰과 종료 함수만 임시 메모리에 둔다.

실시간 답변은 검수 자료·불명 조건 지침에 근거한 모델 생성 음성이며, 발화 전체를 보류한 뒤 문장 일치를 검증하는 이전 coach와 다르다. 지침 준수와 배출 정확도를 보장한 것으로 표시하지 않는다. `/api/call`은 동일 출처 검사와 크기/동시 연결 제한을 적용하지만 사용자 인증은 아니므로 현재 로컬 시험 범위를 공개 서비스로 확대하지 않는다.
