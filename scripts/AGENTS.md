# 배포 빌드와 로컬 HTTPS

`build-sites.mjs`는 동일한 통화 화면과 검수 세션 자료를 Worker 및 공개 정적 자산으로 묶는다. 키·사용자 미디어·학생 제출 문서는 빌드에 포함하지 않는다. `dist`는 생성물이며 직접 편집하지 않는다.

# 로컬 HTTPS 준비와 실행

로컬 개발용 CA·서버 인증서의 준비와 Next HTTPS 실행만 소유한다. 앱 API·모델·배출 규칙·사용자 데이터·.env의 읽기/쓰기와 OS·휴대폰 신뢰 설치는 이 스크립트의 범위가 아니다.

인증서는 현재 프로젝트의 Git 제외 .local-https 안에만 만들고 폴더 0700·파일 0600을 지킨다. 링크·다른 소유자·불완전 자료·다른 준비 작업의 잠금을 자동 수정하거나 덮어쓰지 않는다. staging에서 검증하고 공개하며 실패하면 기존 유효 자료를 보존한다.

CA와 서버 키는 재사용한다. SAN은 localhost와 현재 장치의 정확한 RFC1918 IPv4만 포함한다. 호스트가 바뀌면 서버 인증서만 바꾸고 CA 신뢰는 자동 교체하지 않는다. CA 개인키·서버 개인키를 공유하거나 내용으로 출력하지 않는다.

Next에는 key·cert·CA 파일을 명시하고 기본 HTTP 포트와 다른 HTTPS 포트를 사용한다. 설치되지 않은 도구를 자동 설치하거나 공개 터널을 열지 않는다. 종료 신호는 자신이 시작한 자식 서버에만 전달한다. 준비 전용 모드는 서버를 시작하지 않는다.

검사는 실제 OpenSSL 체인·SAN, CA/키 재사용, 주소 변경, 권한·링크·불완전 구성·명령 실패·잠금 보존을 확인한다. 인증서 생성 성공을 브라우저 신뢰·실물 마이크 성공으로 기록하지 않는다.
